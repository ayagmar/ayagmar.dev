# 0018. CI: one workflow, path-planned jobs, one required gate

Status: accepted, 2026-10-26

## Context

Running every check on every change wastes minutes: a new post does not need the Worker tests, a Worker change does not need a site build. GitHub's path filters make that easy, but a required check that is skipped because of a path filter blocks the merge forever, and a path filter written in YAML can drift from what the jobs need. CI must also never deploy: Workers Builds deploys (ADR 0005) and no Cloudflare credential lives in GitHub.

## Decision

All checks live in one workflow, `.github/workflows/ci.yml`, on `pull_request` and on `push` to `main`. One workflow means one `needs` graph, so a single `gate` job can see every result. CodeQL runs there too rather than in its own workflow, for the same reason.

**Plan.** The first job, `changes`, runs `just ci-plan` (`scripts/ci.ts plan`). On a pull request it lists the files the merge commit changes against its base parent (`git diff --no-renames -z HEAD^1 HEAD`: NUL-separated so no path is quoted, and a moved file counts for both its old and new place; no third-party action); on a push to `main` it plans every job, so `main` is always fully checked. It sorts the files into path groups and outputs one JSON object, `plan`, with a boolean per job. Every other job has `needs: changes` and `if: fromJSON(needs.changes.outputs.plan).<job>`. The groups and the job conditions are written once, in `scripts/ci.ts`; the YAML only reads the plan. A plain `git diff` was chosen over `dorny/paths-filter` because the same code runs locally and in the tests, and it removes a third-party action that reads the event and token.

So a content-only change runs `format`, `secrets-source`, `site-build`, `e2e` and `links`, and skips unit tests, type checks and the Worker. A Worker-only change runs `checks`, `signals-test`, `codeql`, `format` and `secrets-source`, and no site build. Mixed changes run the union. E2e runs on content changes because a new post is a new page and must pass axe and the overflow check.

**Gate.** `gate` has `if: always()` and `needs` every job. It runs `just ci-gate` (`scripts/ci.ts gate`) with the `needs` context: if `changes` did not succeed it fails; each job the plan asked for must be `success`; each job the plan skipped must be `skipped`; a job in `needs` that the plan does not know, or a planned job missing from `needs`, fails it. Branch rules require only `gate`. `just ci-test` runs table tests of plan and gate decisions (content-only, signals-only with a failing type check, a `public/_headers` change, a page change that can break links, a justfile change, mixed changes, a failed or cancelled `changes`) and checks that `ci.yml` defines exactly the planned jobs, that each one is conditioned on its plan entry, and that `gate` needs them all. Adding a job without updating `scripts/ci.ts` fails that test.

**Hygiene.** Top-level `permissions: {}`; each job asks for `contents: read`, and CodeQL also `security-events: write`. Every checkout sets `persist-credentials: false`. No `pull_request_target` or `workflow_run`. One concurrency group per pull request or ref, cancelling superseded pull request runs; pushes to `main` are never cancelled. Every job has `timeout-minutes`. Actions are pinned by full commit SHA with the tag in a comment. A local composite action, `.github/actions/setup`, installs Node from `.node-version`, `just` through `scripts/bootstrap.sh` (sha256-checked, as in Workers Builds), pnpm through corepack (which checks the sha512 in `packageManager`), and the locked dependencies with the pnpm store cached on the lockfile hash. Astro's cache and Playwright's Chromium (keyed on the Playwright version) are cached. Command-line tools (gitleaks, osv-scanner, lychee, actionlint, zizmor, shellcheck, shfmt) are release binaries pinned by version and sha256 in `scripts/bootstrap.sh`, installed on demand by the recipes that use them, so local runs use the same binaries. Every step calls a `just` recipe.

zizmor's `self-repository` audit is disabled in `.github/zizmor.yml`: it asks for `uses: $/...`, which actionlint 1.7.12 rejects. Re-enable it when actionlint accepts the syntax. The one `GITHUB_PATH` write (`.tools/bin`, a fixed workspace path) carries an inline zizmor ignore.

**No Cloudflare in Actions.** CI holds no Cloudflare credential and makes no Cloudflare API call. Offline Wrangler commands that need no token are allowed because the recipes CI shares with local runs and Workers Builds use them: `wrangler types` (`just typegen`), `wrangler deploy --dry-run --outdir` (`just signals-build`) and the local `wrangler dev` Playwright starts. Workflows set `WRANGLER_SEND_METRICS=false` and no `CLOUDFLARE_*` variable. `just ci-policy` (`scripts/ci-policy.ts`, in the `workflows` job) fails if a file under `.github/` calls `wrangler` or names a Cloudflare credential or `wrangler-action`, or if any recipe a workflow runs, with its dependencies, calls a Wrangler command other than `types` or `deploy --dry-run` (each command on a line is checked). It reads each `run:` value with a YAML parser, so a folded (`>`) or multi-line plain scalar is checked as the single command it becomes. It fails closed on what it cannot follow: in a `run:` script, `just` must be one recipe alone on its line (no `&&`, no second recipe, no wrapper), and a recipe body may not call `just <recipe>` itself. `just ci-plan` writes `$GITHUB_OUTPUT` itself for that reason.

**Secrets.** `secrets-source` runs gitleaks over the whole history on every run (redacted). Built output is scanned in the job that builds it, before upload: `scripts/scan-secrets.ts` (private keys, GitHub tokens, Cloudflare `cfk_`/`cfut_`/`cfat_`/`cfoat_`/`cfast_` tokens and legacy 40-character tokens next to a Cloudflare name, AWS, Slack and npm tokens, and high-entropy values assigned to secret-like names) plus gitleaks' own rules, on every file including binary ones (a `.wasm` data section or image metadata can hold a token). The repo's scanner reads each file both as UTF-8 (so Unicode whitespace in text still separates an assignment) and as latin1 (so token bytes in invalid UTF-8 still match). Both scanners always run and print the file, line and rule only: gitleaks runs through `scripts/gitleaks-report.ts`, which discards gitleaks' own output (its verbose excerpt redacts the recognised secret but prints the rest of the match) and reads those fields from a redacted JSON report. The scanner's test plants fake secrets assembled at run time in a temporary directory, so no fixture is ever in the repo, its history or an artifact, and gitleaks needs no allowlist.

**Links.** lychee checks the built site. `https://ayagmar.dev/*` is remapped onto `dist/`, so feed, sitemap and canonical links are checked as local files. `just links` runs offline first (internal links), then online with three retries, a 20 s timeout, 429 accepted and a one-day result cache restored between runs. Exclusions, each explained in `lychee.toml`: `data:` URLs, the colophon's link to the build's own commit, x.com (it answers 403 to CI runners), and `api.ayagmar.dev`. CI builds in fixtures mode (ADR 0015), so the pages also link the sample repositories, releases and tracks in `packages/contracts/fixtures`; `scripts/fixture-urls.ts` turns exactly those URLs into one exclusion, since a sample link going stale says nothing about the site.

**Repo rules.** `just repo-ruleset` (`scripts/repo-ruleset.sh`) creates or updates a ruleset named `main` on the default branch: pull request required with 0 approvals (a solo owner cannot approve their own pull requests), the `gate` check required and bound to the GitHub Actions app (`integration_id` read from a real `gate` check run, so no other app or commit status can satisfy it; the script fails if it finds none), branches not required to be up to date, no force push, no deletion, merge commits as the only merge method, and no bypass actors. It also turns on auto-merge (for Renovate) and keeps merge commits allowed.

**Later jobs.** The resume needs no job of its own: `site-build` compiles it (Typst comes from `scripts/bootstrap.sh` in the setup action) and `e2e` tests it. PR 5 (Lighthouse) adds its jobs at the marked slot in `ci.yml`, an entry in `jobs` in `scripts/ci.ts`, and the job in the gate's `needs`.

## Consequences

Skipped jobs never block a merge and failed ones always do. Adding a check means one entry in `scripts/ci.ts` and one job in `ci.yml`; the test catches a mismatch. A wrong path group either runs too much or skips a check the change needed; the groups err toward running more (toolchain files run everything). External link rot can fail a content PR; the cache and retries keep that to real breakage. The renovate validator downloads Renovate with npm, whose transitive dependencies are not locked; it runs only when tool config changes.
