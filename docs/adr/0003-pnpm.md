# 0003. pnpm as the package manager

Status: accepted, 2026-10-26

## Context

The workspace needs strict dependency isolation (ADR 0002), supply-chain controls and a lockfile Workers Builds can install from.

## Decision

pnpm 12.15.0, pinned in `packageManager` (with its sha512) and in `mise.toml`.
- Strict, non-flat `node_modules`: phantom and cross-app imports fail to resolve.
- `minimumReleaseAge: 4320` in `pnpm-workspace.yaml`: versions younger than three days are refused at install time.
- `allowBuilds`: pnpm 12's allowlist for install scripts (it replaces `onlyBuiltDependencies`). No package may run one. esbuild and workerd are listed `false` explicitly: both find their platform binary through `optionalDependencies` at run time, and their postinstall only replaces a JS shim with the binary. The site build, the Worker tests and `wrangler dev` were verified with no install scripts run.
- `catalog:` pins the versions shared by several packages (`typescript`, `vitest`, `wrangler`, `@types/node`) once, still as exact versions.
- `workspace:*` for internal packages.

npm was the alternative. It hoists dependencies, so an app could import a package it never declared, and it has no release-age gate.

## Consequences

Workers Builds picks pnpm from `packageManager`. A new dependency that needs an install script must be added to `allowBuilds` with a reason, and fails the install until it is.
